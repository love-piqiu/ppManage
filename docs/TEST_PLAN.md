# 测试计划

## 1. 文档概述

本文档描述 ppManage 系统的测试策略、测试范围、测试资源和测试进度安排。

---

## 2. 测试范围

### 2.1 功能测试范围

| 模块 | 测试内容 | 优先级 |
|------|----------|--------|
| 项目管理 | 项目CRUD、里程碑管理、发票管理、进度跟踪 | P0 |
| 问题跟踪 | 问题CRUD、状态流转、预警功能 | P0 |
| 风险管理 | 风险CRUD、等级管理、状态流转 | P0 |
| 人员管理 | 人员CRUD、项目参与关联 | P0 |
| 任务管理 | 任务定义、任务实例、完成率统计 | P0 |
| 周报生成 | 周报预览、邮件发送、定时发送 | P0 |
| 系统管理 | 用户登录、权限控制（继承RuoYi） | P1 |

### 2.2 非功能测试范围

| 测试类型 | 测试内容 |
|----------|----------|
| 性能测试 | 页面加载时间、并发响应 |
| 安全测试 | 认证授权、SQL注入、XSS防护 |
| 兼容性测试 | 浏览器兼容性（Chrome、Firefox、Edge） |

### 2.3 不测试范围

- 第三方组件内部实现（如 RuoYi 框架核心）
- 移动端适配（当前不支持）
- 系统底层运维功能

---

## 3. 测试策略

### 3.1 测试层次

```
┌─────────────────────────────────────────────────┐
│                   E2E 测试                        │
│  (Playwright - 关键业务流程自动化)                │
└─────────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│                 集成测试                          │
│  (API接口测试 - Controller层)                     │
└─────────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│                 单元测试                          │
│  (Service/Mapper层 - 业务逻辑)                    │
└─────────────────────────────────────────────────┘
```

### 3.2 测试方法

| 测试类型 | 方法 | 工具 |
|----------|------|------|
| 单元测试 | 白盒测试 | JUnit + Mockito |
| 集成测试 | API测试 | Postman / RestAssured |
| E2E测试 | 自动化测试 | Playwright |
| 手工测试 | 功能验证 | 人工执行 |

### 3.3 测试覆盖率目标

| 指标 | 目标值 |
|------|--------|
| 单元测试覆盖率 | ≥ 80% |
| API测试覆盖 | 核心接口 100% |
| E2E测试覆盖 | 关键业务流程 100% |

### 4.1 测试环境配置

| 环境 | 用途 | 配置 |

- 预置测试用户：test1/test2/test3
- 预置测试项目：至少5个不同状态项目
- 预置测试问题：各状态各严重程度问题
- 预置测试风险：各等级各状态风险

## 5. 测试用例组织

### 5.1 用例编号规则

```
TC-[模块编号]-[功能编号]-[序号]

示例：
TC-01-01-001  项目管理-项目列表-查询功能
TC-02-03-001  问题跟踪-状态流转-待处理到进行中
```

### 5.2 用例存放位置

- 后端单元测试：`ruoyi-system/src/test/`
- 前端单元测试：`ruoyi-ui/tests/`
- E2E测试：`.gstack/qa-reports/`

### 6.1 测试阶段

| 阶段 | 时间 | 内容 |
|------|------|------|

| 里程碑 | 交付物 |

| 集成测试完成 | API测试报告 |
| E2E测试完成 | 自动化测试脚本、测试报告 |
| UAT完成 | 用户验收确认 |

## 7. 缺陷管理

### 7.1 缺陷等级

| 等级 | 定义 | 处理时限 |
|------|------|----------|
| P0-致命 | 系统崩溃、数据丢失、核心功能失效 | 立即修复 |
| P1-严重 | 主要功能异常、性能严重下降 | 24小时内 |
| P2-一般 | 次要功能异常、界面问题 | 3天内 |
| P3-轻微 | UI瑕疵、提示不友好 | 下版本 |

### 7.2 缺陷状态流转

```
新建 → 确认 → 修复 → 验证 → 关闭
         │       │
         ▼       ▼
       拒绝    无法修复(延期)
```

### 7.3 缺陷记录格式

| 字段 | 说明 |
|------|------|
| 缺陷标题 | 简要描述问题 |
| 详细描述 | 问题现象、重现步骤、预期结果 |
| 缺陷等级 | P0/P1/P2/P3 |
| 所属模块 | 模块名称 |
| 发现版本 | 版本号 |
| 发现人 | 测试人员 |

## 9. 测试准入/准出标准

### 9.1 测试准入标准

- 开发代码已提交并通过编译
- 单元测试覆盖率 ≥ 80%
- 开发提供功能清单和接口文档

### 9.2 测试准出标准

- 所有P0、P1缺陷已修复并验证
- 测试用例执行率 ≥ 95%
- 测试通过率 ≥ 95%
- E2E关键流程测试全部通过

---

## 10. 风险与应对

| 风险 | 应对措施 |
|------|----------|
| 测试时间不足 | 优先执行P0功能测试 |
| 测试数据不足 | 提前准备测试数据集 |
| 环境不稳定 | 预备备用环境 |
| 缺陷修复延迟 | 及时沟通，调整优先级 |
